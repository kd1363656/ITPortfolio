01

何を、なぜ作ったか

ToDo アプリは「登録はするが、開かなくなる」ことが一番の課題だと感じていました。開く理由を作るために、キャラクターが話しかけてくる体験を中心に据えています。

課題 → 解決

予定は登録しても、見返さなければ忘れる。通知だけでは味気なく、すぐ消されてしまう。
→ 開いた瞬間にキャラクターが「残っているタスク」を声で伝え、終わるほど笑顔になる。「見に行く」のではなく「教えてもらう」ToDo にした。

🔊声で伝える

その日初めて開いたときは、未完了のタスクを時刻順に読み上げ、最後に応援の一言。2回目以降は季節と地元の話を少しして、残りの量に合わせた一言を添えます。

英語のタスク名も「Zoom meeting → ズーム ミーティング」とカタカナに変換して読みます。

🙂表情と口パク

再生中の音の大きさ（RMS）を 1/30 秒ごとに測って口の形を切り替え、ふだんはランダムな間隔でまばたき。全部終わると笑顔、夜は眠そう、残りが多いとジト目になります。

🎨キャラごとに変わるアプリ

6人のキャラクターは、立ち絵・声・口調・テーマカラーをすべて JSON で持っています。キャラを選び替えると、配色が溶けるように変わり、セリフの語尾も声も変わります。

02

画面

3つのタブ（今日のタスク／一年のタスク／設定）と、右下の＋ボタンから出るタスク入力シート。すべてエミュレータ（Android 16, API 37）で動かしたスクリーンショットです。

03

動きと演出

「出る・消える・切り替わる」ものには必ずイージングのアニメーションを付ける、というルールで作っています。目を引くことも、ToDo を開いてもらうための機能だと考えているからです。

口パク（リップシンク）

AudioTrack に 1/30 秒ぶんずつ書き込みながら、その区間の RMS（音の大きさ）を計算して「閉じ・う・お・あ」の口画像に差し替えます。実際の読み上げ中の連続スクリーンショットです。

達成のコインフリップ

完了するほど縁取られていくリングが、全部終わると rotationY で1回転して裏面のチェックに。裏を向いている間は中身を 180° 戻し、文字が鏡像にならないようにしています。

表情は状況から決まる

お祝い中 > 全部完了 > セリフ指定 > 夜 > 通常 の優先順位を when 1つで表現。まばたきは 2〜5 秒のランダム間隔で、20% の確率で2回連続（機械っぽさを消すため）。

6人ぶんの配色・口調・声

キャラを替えると色が Animatable で溶けるように変わり、吹き出しの語尾（「〜です」「〜なのだ」）と VOICEVOX の話者も切り替わります。

スワイプで削除

anchoredDraggable で「閉じ／開き」の2点に吸い付くスワイプ。開いた割合に合わせて赤い背景が伸び、ゴミ箱アイコンが濃く大きくなります。

「いま」の強調とタブ復帰の反応

開始時刻を過ぎた未完了タスクのうち一番新しいものを色と「いま」ラベルで強調。別のタブから戻ると、前回と違う雑談を1つ話します。

01 · 音声エンジンを差し替えられる形で C++ を組み込む

VoiceEngine インターフェース + C++17 JNI ブリッジ

VOICEVOX CORE は C の API しかないので、C++ で JNI の薄い橋を書き、Kotlin 側は VoiceEngine というインターフェースだけを見ています。AquesTalk など別エンジンへの差し替えが仕様上決まっているため、最初から抽象化しました。

  • RAII：GetStringUTFChars の返却をデストラクタに任せ、途中 return でもリークしない。
  • 失敗は Kotlin の例外に：エラーコードを ThrowNew で IllegalStateException に変換し、Kotlin 側は try/catch だけで扱える。
  • ハンドルは jlong：C++ 側の構造体のアドレスを数で往復させ、Kotlin はポインタを知らない。
  • Mutex で直列化：合成は重い計算なので Dispatchers.Default + Mutex.withLock。synchronized と違いコルーチンを止めずに順番待ちできる。

/** Kotlin の文字列(jstring)を C の文字列として借りる入れ物、
 *  デストラクタで必ず返すので、途中で return しても借りっぱなしにならない(RAII)*/
class Utf8String {
public:
    Utf8String(JNIEnv* env, jstring text)
        : env_(env), text_(text), chars_(env->GetStringUTFChars(text, nullptr)) {}
    ~Utf8String() { env_->ReleaseStringUTFChars(text_, chars_); }
    const char* get() const { return chars_; }
private:
    JNIEnv* env_; jstring text_; const char* chars_;
};

/** 失敗していたら Kotlin 側に例外を投げて true を返す*/
bool throwIfFailed(JNIEnv* env, VoicevoxResultCode result, const char* step) {
    if (result == VOICEVOX_RESULT_OK) return false;
    std::string message = std::string(step) + ": " + voicevox_error_result_to_message(result);
    env->ThrowNew(env->FindClass("java/lang/IllegalStateException"), message.c_str());
    return true;
}

02 · 口パクを「音の大きさ」から作る

再生しながら RMS を測り、口の形に変換する

WAV を一度に流すのではなく、AudioTrack（MODE_STREAM）に 1/30 秒ぶんずつ書き込みます。write() はバッファが空くまで待つので、「いま鳴っている部分」の大きさをそのまま口の形に使えます。

  • WAV ヘッダを自前で読む：チャンクを先頭から走査し、fmt からサンプリングレート、data から音の位置を取る。LIST など知らないチャンクは読み飛ばす。
  • 境目は定数に：0.15 / 0.4 / 0.7 で「閉じ・う・お・あ」。マジックナンバーは必ず名前を付ける。
  • キャンセルに強い：isActive を見て次の切れ目で止まり、finally で必ず口を閉じて pause → flush → stop → release。タブを離れた瞬間に黙る。
  • 再コンポーズを抑える：口の形は高頻度で変わるので、画面全体ではなく Canvas の描画だけが更新されるよう、値ではなく StateFlow / ラムダで渡す。

/** 1秒の音を何個に切って流すか、30 なら 1/30 秒ごとに音の大きさを知らせるので、口パクが画面の動きに間に合う*/
private const val ChunksPerSecond = 30

val chunk = ShortArray(format.sampleRate / ChunksPerSecond)
// isActive を見るので、キャンセルされたら次の切れ目で止まる
while (samples.hasRemaining() && isActive) {
    val count = minOf(chunk.size, samples.remaining())
    samples.get(chunk, 0, count)
    onLevel(levelOf(chunk, count))
    // write() はバッファが空くまで待つので、音が鳴る速さに合わせて進む
    track.write(chunk, 0, count)
}

/** 切れ目の音の大きさを RMS(2乗の平均の平方根)で求め、0〜1 にそろえる*/
private fun levelOf(samples: ShortArray, count: Int): Float {
    var sum = 0.0
    for (index in 0 until count) {
        val sample = samples[index] / Short.MAX_VALUE.toDouble()
        sum += sample * sample
    }
    val rms = sqrt(sum / count).toFloat()
    return (rms * LevelGain).coerceIn(SilentLevel, LoudestLevel)
}

 *  小さい境目から並べると「どの境目より小さいか」で決まる*/

    level < MiddleMouthLevel -> Small   // 0.4  「う」

03 · キャラクターを「コード」ではなく「データ」で持つ

PSD → JSON の書き出しツールと、1色から作る配色

6人分の立ち絵は PSDTool 形式の PSD です。Python（psd-tools）でレイヤーを切り替えながら「口なしの土台」「口の差分 6 種」「目の差分 5 種」を書き出し、貼り付け位置・バストアップの切り抜き・声・口調・テーマカラーを character.json にまとめます。

  • キャラ追加 = PSD を置いてツールを実行するだけ。Kotlin のコードは1行も変えない。
  • セリフも JSON：語尾（〜です／〜なのだ）はキャラごとに違うので、文全体を %1$d 付きの書式で持たせる。読み間違えやすい文は AquesTalk 風のカナも併記。
  • 配色は seedColor 1色から：HSL の色相を保ったまま明るさ（トーン）を変えて Material 3 の ColorScheme を組み立てる。彩度の下限を 0.35 にして、灰色っぽい色でも「色が付く」ようにした。
  • 知らないキーは無視：ignoreUnknownKeys = true でツール側に項目を足しても古いアプリが落ちない。

/** 彩度(色の鮮やかさ、0〜1)の決まり、
 *  元の色が灰色に近くても色が付くように最低値を決め、
 *  secondary や背景(neutral)は元の鮮やかさを何倍に弱めるかで落ち着いた色にする*/
private const val MinSaturation = 0.35F
private const val SecondarySaturationScale = 0.4F
private const val NeutralSaturationScale = 0.12F

/** 1つの色から、色相(色合い)は同じまま明るさだけを変えた色を作る道具*/
private class TonalPalette(seed: Color) {
    private val hue: Float
    private val saturation: Float
    init {
        // colorToHSL は渡した配列に結果を書き込む(C++ の出力引数と同じ)
        val hsl = FloatArray(HslComponentCount)
        ColorUtils.colorToHSL(seed.toArgb(), hsl)
        hue = hsl[HueIndex]
        saturation = hsl[SaturationIndex].coerceAtLeast(MinSaturation)
    }
    fun primary(lightness: Int): Color = tone(lightness, PrimarySaturationScale)
    fun neutral(lightness: Int): Color = tone(lightness, NeutralSaturationScale)
    private fun tone(lightness: Int, saturationScale: Float): Color =
        Color(ColorUtils.HSLToColor(floatArrayOf(hue, saturation * saturationScale, lightness / 100.0F)))
}

04 · 「何を話すか」を純粋な関数に閉じ込める

台本（TodaySpeechScript）は画面も音声も知らない

セリフの組み立ては object TodaySpeechScript に集め、入力はタスク一覧・キャラのセリフ定義・時刻だけ。Android の部品に触らないので、端末なしの JUnit で一瞬で確かめられます（9 本のテスト）。

05 · 「今日」が変わる瞬間まで面倒を見る

日付をまたぐ Flow と、通知予約の自動同期

アプリを開いたまま 0 時を過ぎると「今日」がずれる、という不具合を設計レビューで見つけ、observeToday() という Flow にしました。次の 0 時までの時間だけ delay して新しい日付を流すので、今日のタスクも通知の予約も自動で切り替わります。

  • 予約の計算は純粋に：ReminderPlan.alarmsFor() は「通知 ON・未完了・今より後」だけを残す関数。単体テスト 4 本。
  • 監視は 1 か所：ReminderSync がタスクと設定を combine し、変わるたびに replaceAll()。画面ごとに予約コードを書かない。
  • AlarmManager の制約を吸収：正確なアラームの許可がなければ 10 分幅の setWindow に落とす。再起動後は BootReceiver から syncOnce()。

data/time/Today.ktKotlin
/** 今日の日付を流し、日付が変わった瞬間(0時)に次の日付を流す、
 *  アプリを開いたまま日をまたいでも「今日」の表示や通知の予約が新しい日に切り替わる*/
fun observeToday(): Flow<LocalDate> = flow {
    while (true) {
        val now = LocalDateTime.now()
        emit(now.toLocalDate())
        // 次の0時までの時間だけ待つ、delay() はスレッドを止めずに待つので他の処理の邪魔をしない
        val nextMidnight = now.toLocalDate().plusDays(1).atStartOfDay()
        delay(Duration.between(now, nextMidnight).toMillis())
    }
}
data/reminder/ReminderSync.ktKotlin
/** アプリが動いている間ずっと見張りを続ける、VoiDoApplication.onCreate() から1回だけ呼ぶ*/
fun start() {
    scope.launch {
        observeToday()
            // 日付が変わったら、前の日の見張りをやめて新しい「今日から先」の見張りに切り替える
            .flatMapLatest { today -> observeAlarmsFrom(today) }
            .collect { alarms -> reminderScheduler.replaceAll(alarms) }
    }
}

/** タスクか通知設定のどちらかが変わるたびに、両方の最新値で計算し直す*/
private fun observeAlarmsFrom(today: LocalDate): Flow<List<ReminderAlarm>> =
    combine(taskRepository.observeReminderTasksFrom(today),
            settingsRepository.isNotificationEnabled) { tasks, isNotificationEnabled ->
        ReminderPlan.alarmsFor(tasks, LocalDateTime.now(), isNotificationEnabled)
    }
06 · UI の細部にも「理由のある書き方」を

スワイプ削除・並び順・再コンポーズの抑制

見た目の部品でも、状態の持ち方と更新のコストを意識しています。

  • 開き具合はラムダで渡す：スワイプ中は 1 フレームごとに値が変わる。revealFraction: () -> Float にして drawBehind / graphicsLayer の中で読むと、再コンポーズせず描画だけが更新される。
  • 並び順は 1 行の純粋関数：「未完了が上・完了が下、各時刻順」は sortedBy { isCompleted }。安定ソートなので Room の時刻順を崩さない。SQL ではなく Kotlin にしたのは、単体テストで一瞬で確かめるため。
  • 行の移動はタダで付いてくる：LazyColumn に key = id と animateItem() を付けてあるので、チェックした行はふわっと下へ移動する。
  • 状態ホイスティング：下部バーもスイッチも自分で状態を持たず、selected と onSelected を上から受け取る。Preview で好きな状態を表示でき、使い回せる。

06

設計の考え方・自分に課したルール

「あとで読む人（未来の自分を含む）が、なぜそうなっているか分かるコード」を目標にしています。チーム開発を想定して、すべてのファイルで同じ決まりを守りました。

01
層を分け、依存は内側へ（MVVM + Repository + DI）

画面は ViewModel の StateFlow を見るだけ。ViewModel はインターフェース（TaskRepository / VoiceEngine…）だけを知り、Hilt の @Binds が実装を差し込む。テストは偽物に差し替え。

02
判断は純粋な関数に切り出す

台本・通知の対象・表情・並び順・カレンダーの日付計算は Android に依存しない関数（xxxOf()）にし、単体テストで確かめる。

03
マジックナンバーを書かない

見た目の数値はファイル先頭の定数に、名前は [何の][性質][単位]（例：BlinkIntervalMinMillis、TaskBarAccentWidth）。ただの数のときだけ単位を付ける。

04
コメントは WHY を書く

「何をしているか」はコードが語る。「なぜ Mutex で synchronized ではないのか」「なぜ CancellationException を先に catch するのか」をコメントに残す。

05
入れ子は 2 段まで

3 段目になったら関数に分ける（VoiDoScaffold / VoiDoTabContent / TodayTab…）。長い引数リストは名前付き引数で縦に揃える。

06
命名規則を文書化して守る

Boolean は is/has/can/should、イベントは onXxx、Flow は observeXxx、テストは 対象_ふるまい。ラムダ引数は必ず名前を付け it を使わない。略語を使わない（previousDescription）。

07
YAGNI は「仕様にないもの」にだけ

仕様で決まっている機能（別の音声エンジン、口パク）は「今必要なもの」として最初から構造を用意する。「いつか使うかも」のフックは作らない。

08
仕様変更は、消す・直す・確かめるをその日に

一年のタスクからキャラを外したときは、画面 → つなぎ → データ型 → 書き出しツールまで逆順にたどって不要物を全部消した。変更には必ずテストを添える。

つまずいたこと と 解決

PROBLEMVOICEVOX CORE の .so を Android に組み込むと、PC のパスが DT_NEEDED に焼き込まれて実機で見つからない。
SOLVEDllvm-readelf -d で依存を確認。配布 .so に SONAME が無いのが原因と分かり、CMake の IMPORTED ライブラリに IMPORTED_NO_SONAME TRUE を指定。
PROBLEMONNX Runtime を実行時に読み込む API が、APK 内の .so を開けない。
SOLVEDAPK のライブラリは展開されないため、Kotlin 側で先に System.loadLibrary("voicevox_onnxruntime") し、C++ にはファイル名だけ（libvoicevox_onnxruntime.so）を渡して dlopen させる。
PROBLEM「爪切り」「風邪薬」などを読み間違える。
SOLVEDOpen JTalk の辞書を pyopenjtalk-plus の辞書に差し替え（SHA-256 で出所を記録）。それでも固定したい文は AquesTalk 風記法のカナを JSON に併記し、synthesizeKana() で読ませる。辞書の版が上がったら古い版のフォルダを端末から消す処理も追加。
PROBLEMアプリを開いたまま日付が変わっても「今日」が昨日のまま。時計も古い時刻のまま。
SOLVED設計レビューで発見。observeToday() Flow と、分が変わるたびに再描画する rememberCurrentTime() を導入し、通知予約も flatMapLatest で切り替え。
PROBLEM口パク中に画面全体が再コンポーズされてカクつく。
SOLVED高頻度で変わる値（口の形・スワイプ量）は StateFlow／ラムダで渡し、Canvas や graphicsLayer の中で読む。CompositingStrategy.Offscreen で DstIn のぼかしが背景まで透過する問題も解決。
PROBLEMAGP 9 の設定キャッシュで doFirst { check(...) } が禁止され、ライブラリ存在チェックが書けない。
SOLVEDチェックを設定時（configuration time）に移動し、sourceSets.main.jniLibs.directories.add() の新しい書き方に合わせた。
